# SMOKESHOW for iOS and macOS

One SwiftUI codebase, two platforms, plus a WidgetKit extension, a Live
Activity, and a watchOS complication bundle. Native throughout — no WebView
wrapper anywhere (platform plan §2: a thin wrapper invites Guideline 4.2, and a
paid subscription on one invites more scrutiny, not less).

```
apple/

  project.yml                XcodeGen spec: app, widgets, watch, tests
  Makefile                   generate · test · tokens · fixtures
  Configuration/             entitlements, Smokeshow.storekit
                             (Info.plists are generated from project.yml)
  Sources/
    SmokeshowKit/            everything shared
      Contract/              /api/forecast v1 as Swift — a decoder, not a domain model
      Data/                  client, cache, repository, prefs, mock endpoint, deep links
```

## Build

```sh
brew install xcodegen          # once
make sync                      # regenerate tokens + fixtures from the repo's sources
make generate                  # → Smokeshow.xcodeproj
make test                      # SmokeshowKit tests, no project required
open Smokeshow.xcodeproj
```

Set `DEVELOPMENT_TEAM` in the environment before `make generate` for signing,
and `REVENUECAT_API_KEY` for billing. Without the key the app runs on
`StubEntitlementProvider`, so the simulator and CI work with no store at all.

## The rule this codebase is organised around

**Render, don't compute.** `/api/forecast` returns the fully-derived verdict —
level, clear-time, arrival, peak, trend, day summaries, sky, and the measured
rows — and the clients render it. There is no `computeVerdict` in Swift, no
rating ladder, no 6-hour hold, no 35 µg/m³ anywhere in the code. `ParityTests`
fails the build if one appears.

That is not tidiness. It is the product's only promise: a user whose phone says
*clears 6 PM* and whose laptop says *clears 9 PM* has caught you being wrong
(platform plan §2). Two consequences you will notice while reading the code:

- `verdict.headline`, `clearLabel`, and every string in `scale[]` are rendered
  **verbatim**. The tilde in "Thursday ~6 PM" is required — the forecast is an
  estimate and the label has to say so.
- A `null` hour renders as `—`, never as `0`. Zero µg/m³ is a claim about clean
  air, and the model returns null for hours it has nothing to say about.

Every forecast label carries "model estimate", and past hours are labelled
model estimate too — never "observed". They are model reanalysis.

## The widget budget

WidgetKit allows roughly 40–70 timeline reloads per widget per day. This app
asks for **8–16**, because one fetch returns a whole timeline and
`TimelineBuilder` slices ~24 entries out of it:

| state | refresh | network calls/day | entries per call |
| --- | --- | --- | --- |
| smoke active | 90 min | 16 | 25 (12 h @ 30 min) |
| calm | 3 h | 8 | 25 |
| lapsed | 6 h | 4 | 1 |
| unavailable | 20 min → 2 h backoff | ≤ 12 | 1 |

Nothing polls. The extra reloads are all event-driven: app foreground, place
change, preference change, entitlement change, and a silent push from B7 that
says the verdict moved. `TimelineBuilderTests` asserts the cadences.

## What is mocked, and what is real

| Dependency | State |
| --- | --- |
| `/api/forecast` | **Real contract, real fixtures.** `Resources/Fixtures/*.json` are generated by running synthetic series through the actual payload builder (`src/lib/forecast.js`) and validated against `design/forecast-api-v1.schema.json` before they are written. They cover every case in contract §10. |
| `design/tokens.json` | **Real.** `Tokens.generated.swift` is generated from it; `ParityTests` re-checks the values against the JSON. |
| Notification registry | **Integrated.** `DeviceRegistry.swift` implements the `/v1/devices` contract, stores the one-time bearer credential in the Keychain, and sends the same anonymous ID RevenueCat uses. The service URL is injected with `NOTIFICATION_SERVICE_BASE_URL`. |
| RevenueCat | **Real integration, compiled conditionally.** All SDK calls are behind `#if canImport(RevenueCat)`; the package is added by the Xcode project, not by `Package.swift`, so `swift test` runs without it. |
| App Store Connect | Product ID `earth.smokeshow.subscription.monthly`, group `smokeshow`, $2.99/month, 14-day introductory offer — mirrored in `Configuration/Smokeshow.storekit` for local StoreKit testing. |

### Verified, and not

The Swift was written in a Linux container with no toolchain, so the compile
pass happens in CI on macOS runners (`.github/workflows/ci.yml`). As of the
latest push, all four jobs are green:

| Check | What it proves |
| --- | --- |
| `web tests` | the web suite still passes (145 tests) |
| `generated artifacts are current` | tokens and fixtures match their sources, and every fixture still validates against the v1 schema |
| `SmokeshowKit tests` | the shared framework compiles and its 38 tests pass — decoding, the timeline budget, trial/lapse policy, and the parity guards |
| `iOS + macOS build` | the app, the widget extension, the Live Activity, and the watch app compile and link for iOS Simulator, macOS, and watchOS Simulator |

Seven real defects came out of that loop: line-continuations in non-multiline
string literals, watchOS inside `supportedDestinations`, an Xcode-16 pbxproj
format the runner could not open, a `Double?` in `ParityTests`, RevenueCat
linked to the app instead of the kit that imports it, an iOS-18-only
`WidgetCenter.currentConfigurations()`, and hand-written Info.plists that broke
the AppIntents build phase.

**What CI does not prove**, and still needs a Mac and a device:

- that the widgets *look* right — `systemLarge` and `systemExtraLarge` were
  designed without ever being rendered, place-name truncation at 148pt is
  untested, and the `isDark` ink inversion needs a contrast audit;
- that billing works — no App Store Connect product exists yet, so the
  trial → day 14 → lapse path has never run against a real receipt;
- that the watch is correct — see `docs/watch-and-live-activity.md` for the
  one known correctness gap (entitlement transfer over WatchConnectivity).

## Copy sign-off still open

`Copy.disclaimer` ships the brief's text verbatim, as CLAUDE.md requires, and
`ParityTests.testDisclaimerMatchesTheBriefWordForWord` enforces it. The live web
page renders a slightly different variant ("Smokeshow" in sentence case, a comma
where the brief has an em dash). Platform plan §10.1 already lists copy as open;
if the web's variant is the intended one, change the brief and both surfaces
follow.
